## The Runbook

- **Trigger:** a new agent's agreement is signed and a start date is set, or a role change is approved. Run it as soon as the start date is set.
- **Who:** Barnaby Kettlewhite (Director of Operations) runs it; Rosalind Puddingstone (Team Leader) approves the plan; Hollis Fernsby (Principal Broker) confirms the license.
- **Required data:** the current onboarding-setup.md, and the agent's name, role, start date, experience and license status. Helpful: the mentor (Odette Brambleworth or Cassius Wheatley, as Rosalind assigns) and anyone else in a checkpoint.
- **Steps:** 1) Start a new chat with the skill on, attach the setup, and give the details. 2) Settle Needs Your Answer first. 3) Rosalind reads the plan. 4) Name a real person for every checkpoint and tell them. 5) Send the welcome note yourself. 6) Put the checkpoint dates in your own calendar or task tool.
- **Human judgment points:** the standards; which version wins a conflict; the license confirmation (Hollis); every checkpoint owner; every decision about the person; anything legal.
- **Repair:** when a plan is wrong, find the step's source in the plan. If the setup is wrong, fix the setup (or the handbook or checklist), raise the version to 1.1 with a change log line, rerun the three tests and record them, then rerun the plan. If the skill adds something that isn't in the setup or drops a hold, rerun once; if it happens again, write down the expected result, the actual result, a redacted input, what you tried and the app, and bring it to your office hours or support.
- **Refresh:** whenever the handbook, the checklist, the roles list or a standard changes. Rerun the three tests after every version change.
- **Fallback:** if the AI tool is down, the setup file is the checklist. Run it by hand.
- **Status:** "Tested and ready" once the three tests pass. "Adopted" only after a real new agent's plan was used and reviewed. Don't call it time saved until the time is measured.
